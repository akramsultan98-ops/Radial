# Security and privacy

## Principles

- **Local only.** RADIAL makes no network requests of its own: no uploads, accounts, telemetry,
  analytics, update checks or crash reporting. (On Windows 10 the *installer* may download the
  WebView2 runtime from Microsoft if it is missing.)
- **Never modify or execute inputs.** Source files are opened read-only. Executables are recognised
  by signature and refused.
- **Never overwrite.** The output can't be the original, existing files are never replaced, and the
  final move uses an atomic no-clobber rename.
- **No sensitive content in logs or history.** History stores names, paths, formats, status and
  error categories only.

## Desktop permissions

The webview runs with a strict Content-Security-Policy (`default-src 'self'`, no remote scripts,
`object-src 'none'`, `frame-ancestors 'none'`) and the Tauri capability in
`src-tauri/capabilities/default.json` grants only:

- `core:event:default`, `core:webview:default`, `core:window:default` — events, drag-and-drop
  notifications, window basics;
- RADIAL's own commands, each listed explicitly (generated by `src-tauri/build.rs`).

The webview gets **no** `fs`, `dialog`, `shell` or `opener` permissions. Native dialogs and
"open/reveal" run inside Rust commands.

## Path allowlist

Every command that touches a path checks it against a per-session allowlist (`src-tauri/src/access.rs`):

| Source of a path | Grants |
| --- | --- |
| Native open dialog, drag-and-drop, launch arguments | read that file; write into its folder |
| Native folder picker / saved default destination | write into that folder |
| A finished conversion | read (preview) / open / reveal that output |
| History entry | open / reveal its recorded output; retry re-imports its source |

A compromised or buggy frontend therefore cannot read, write or open arbitrary locations.

## Malformed and hostile files

- Type detection is content-based; the decoder is chosen from the signature, not the extension.
- Decoding enforces limits (30 000 px per side, 2 GiB per allocation) and files over 1 GB are
  refused, preventing decompression bombs from exhausting memory. A PNG header claiming
  40 000 × 40 000 px is rejected before any pixel data is read (tested).
- Truncated and corrupt files fail with a classified error and leave no output (tested).
- Encoders write to a hidden temp file in the destination folder; the result is decoded again and
  checked before it is moved into place.

## External engines (future)

When FFmpeg or LibreOffice support lands, engines will be invoked with `std::process::Command` and
an argument list — never through a shell, and never with file names interpolated into a command
string. Inputs will be passed as paths after validation; outputs will follow the same
temp-file → verify → no-clobber rename contract.
